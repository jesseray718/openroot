Globally, this supports a commons connecting local computing, appropriate technology, shared evidence, attribution, and correction. Distributed adoption, physical-system performance, and ACRE economics each require separate evidence.

This publication ships documentation, not local-only implementation files or raw evidence. Receipt hash prefixes are discovery leads, not sufficient verification identities. No private payload, credentials, machine paths, or forensic archive details are included.

## Remaining complete-system build and acceptance list

Search for existing work before implementing each item. Classify it FOUND_AND_VERIFIED, FOUND_NOT_VERIFIED, PARTIAL, MISSING, or BLOCKED.

- Canonical installed CLI/API route with tested cache-first behavior and explicit local/remote transport.
- Ingestion provenance, stable identities, controlled duplicates, FTS consistency, update/deletion rules, and original-payload references.
- Explicit bounded versus exhaustive retrieval, authority-aware selection, deterministic tie policy, protected primary-evidence budget, and useful relevant excerpts.
- Correction authority, scope, supersession, replacement evidence, ask-time precedence, and concurrency-safe readers/writers.
- Strict pathway validation, applicability/freshness rules, corruption and drift handling, and versioned migration compatibility.
- Request accounting, failures, timeouts, secret protection, and no unreported model fallback.
- Metering boundaries distinguishing measured energy, estimated energy, timing, and token usage.
- Off-device backup, consistent writer-aware capture, ledger/payload/configuration recovery, and restore drills.
- Pod-to-pod sync/merge with identity, conflict, duplicate, provenance, and chain-continuity rules defined before implementation.
- Optional native-BLAKE3 support only as a reviewed additive migration; legacy seals remain untouched.
- Edge-device acceptance with actual device-specific receipts; no assumed ESP32 or disconnected operation.
- Portable pathway sharing, access control, imported correction trust, revocation, and version compatibility.
- Clean-clone reproduction, named-file implementation commits, dependency completeness, installation/rollback instructions, and verified publication/deployment.
