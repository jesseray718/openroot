## 3. THE WORKFLOWS DEFINED THIS WINDOW (full architecture)

### 3.1 The Chain (lessons.db hash-chained ledger)
Every mistake/error/event is bound by SHA256(stage + error + exit_code), stored
in SQLite on OptiPlex. Tamper-evident: changing a row breaks the prev-hash chain.
Purpose: mistakes become searchable, chained inputs — terminal scrollback dies,
knowledge compounds. First table this window: lessons(ts, stage, error, exit_code, sha256).

### 3.2 Cache (non-recompute principle)
Verified solutions (proofs, measurements, compiled artifacts) get cached with
their hash so they are NEVER recomputed. Lookup-first, compute-second. The
refinery's evidence-gated promotion is the enforcement mechanism: no artifact = no advance.

### 3.3 Ledger (superlinear compounding)
Three mobile ledgers + OptiPlex canonical data/ as the merge point. Every sync
appends a prev-hash-chained entry to ideas.jsonl. Ideas accumulate provenance
(source, raw_hash, permaculture principles activated, eta_human_proxy).

### 3.4 Mistake → Solution hash binding
A mistake's sha256 links to its solution's sha256 via a link_sha — one-way
durable pairing. When a new error occurs, hash it, look it up FIRST; if the
hash (or fuzzy-match on normalized error text) exists in the chain, replay the
recorded solution instead of re-debugging. This is the core non-recompute pathway
for KNOWLEDGE (cache covers COMPUTATION).

### 3.5 Evidence-gated state machine (refinery)
raw → grounded → schema_bound → graded → thermal_checked → production_ready.
Promotion requires a verifiable artifact on disk (file, row, measured value) —
assertions are worthless; only grep-verifiable evidence advances state.

### 3.6 Bot loop (autonomy layer)
watch (ledger hash deltas) → sync (unifier) → refine (worker) → absorb (lessons.db).
Turns the entire pipeline from human-triggered into a persistent, self-recording,
failure-learning loop. eta = J_useful/J_human rises every cycle the human does nothing.
