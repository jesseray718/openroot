# Open-Source Project Cross-Reference ranked by η³ merger value for OpenRoot

η³ proxy used here: (alignment with Agape + physical/useful work + offline capability + low capture risk) × (ease of merge or complementary yield) / (integration cost)

## Tier S — highest merger value
| Project / class | Why high η³ | What OpenRoot gains | What we can push back |
|-----------------|-------------|---------------------|------------------------|
| Community mesh / offline-first networks (e.g. Nimble-style, Freifunk-related, awesome-mesh ecosystem) | Directly raises lowest connectivity nodes; offline native | Real radio + routing + deployment patterns for the icosahedral mesh | Agape hand-up rules, zero-dep ledger, ranked knowledge payload |
| Mutual-credit / complementary-currency ledgers (Trustlines-class, local exchange systems) | Non-extractive capital coordination | Battle-tested mutual credit flows to combine with leveling pools | Lowest-node-first coefficient + automatic hand-up + anti-whale caps |
| Proof-of-useful / physical-work research (PoUW, DePIN physical-work theses) | Aligns with ACRE / PoPW direction | Verification patterns for physical yield | Strict Agape attestation (benefit at recipient) and open knowledge requirement |

## Tier A — strong complementary
| Project / class | Why | Gain for OpenRoot | Push-back |
|-----------------|-----|-------------------|-----------|

| Offline knowledge / library systems | Direct support for mesh-data seeds | Distribution and search patterns | Survival resolver + bioregional packs |

## Tier B — selective merge
- Specific rocket-mass-heater, water, and natural-building open documentation sets (Permies-adjacent and independent)
- Public-domain / open tree and plant keys that can be localized to SE Missouri
- Small ZK attestation libraries only when recipient privacy becomes a real requirement

## Explicit low-η³ (avoid or isolate)
- Pure speculative token projects with no physical yield
- High-energy PoW systems
- Projects that require permanent cloud or privileged admin keys
- Anything that re-introduces owners above the ledger

## Merger operating rule
1. Fork or submodule only what passes Agape predicates
2. Keep OpenRoot’s zero-dependency and offline paths intact
3. Push improvements back upstream when they also raise the lowest node for that project’s users
4. Record every merger as a ledger opportunity/acceptance so the circuit stays visible
