# OpenRoot v1.0 Definition — Production Release Criteria

> *v1.0 = production readiness. Not "perfect." Ready for external validation and adoption.*

## What v1.0 Means

OpenRoot v1.0 ships when **all five pillars are physically validated**, not just documented. Theory is complete when data confirms it.

## Five Pillars of v1.0

### 1. Energy Engine (Thermal Cascade H-003) ✅ REQUIRED

**Deliverable:** 30-day continuous data log from physical prototype

| Metric | Target | Source |
|--------|--------|--------|
| Nightly kWh capture | ≥12.91 kWh/m² (±15%) | Simulation: 12.91 kWh/m² |
| ΔT (inlet → outlet) | ≥20°F on 95°F days | Ground-source heat pump baseline |
| Airflow CFM | ≥500 CFM sustained | Natural convection + chimney effect |
| Humidity reduction | <30% RH at exhaust | Desiccant + evaporative cooling |
| Wet cure confirmation | 21 days minimum | Hard Rule #2 |

**Acceptance Criteria:**
- [ ] Data logged twice daily (06:00 and 18:00) for 30 consecutive days
- [ ] JSONL format published to Zenodo + IPFS
- [ ] Sensor calibration documented
- [ ] Failure modes recorded honestly (Hard Rule #7)
- [ ] Peer review from at least one thermal engineer

### 2. Material Engine (AE-GFRC) ✅ REQUIRED

**Deliverable:** Lab-verified aerated concrete formulation

| Test | Target | Method |
|------|--------|--------|
| Porosity | 70-85% | Water displacement + density measurement |
| Compressive strength | ≥500 psi | ASTM C109 cube test |
| Foam stability | ≥21-day cure | No bubble collapse at week 3 |
| Thermal conductivity | ≤0.5 W/m·K | Guarded hot plate method |

**Acceptance Criteria:**
- [ ] Mix formula published with xanthan gum ratios
- [ ] 3 independent batches tested
- [ ] Strength data logged
- [ ] Microscopic photos of pore structure
- [ ] Comparison vs control (non-aerated concrete)

### 3. Finance Engine (ACRE Token) ✅ REQUIRED

**Deliverable:** Working validator smart contract on Solana devnet

| Feature | Implementation |
|---------|----------------|
| Two-validator approval | Multi-sig wallet or on-chain voting |
| Novelty scoring | 0-10 scale with evidence links |
| Mint trigger | 2/2 approvals + oracle confirmation |
| Anti-spam | Rate limit (1 claim per validator per week) |

**Acceptance Criteria:**
- [ ] Smart contract deployed to Solana devnet
- [ ] CLI validator tool functional (Python/TypeScript)
- [ ] At least one mock claim processed end-to-end
- [ ] Audit by one external security reviewer
- [ ] Gas cost analysis (<0.01 SOL per mint target)

### 4. Governance Engine (Spoke Nodes) ✅ REQUIRED

**Deliverable:** Deployable spoke node with offline capability

| Component | Specification |
|-----------|--------------|
| Hardware | Raspberry Pi 4 / Mini PC |
| Local LLM | Qwen2.5-Coder-1.5B (GGUF, quantized) |
| Storage | IPFS pinning + local SQLite index |
| Mesh protocol | libp2p or LoRaWAN |
| Power | Solar-charged battery buffer |

**Acceptance Criteria:**
- [ ] Spoke template forkable + deployable in <1 hour
- [ ] Offline LLM serving local queries (≥50 tokens/sec)
- [ ] IPFS pin persistence (survives reboot)
- [ ] Mesh peer discovery functional
- [ ] Power draw <5W sustained

### 5. Knowledge Engine (Handbook) ✅ REQUIRED

**Deliverable:** Unified, searchable documentation

| Section | Length | Format |
|---------|--------|--------|
| Philosophy | 20 pages | Markdown → PDF |
| Financial Path | 30 pages | Excel calculator + PDF |
| Energy Systems | 50 pages | Diagrams + equations |
| Material Science | 40 pages | Mix sheets + photos |
| Governance | 30 pages | Axioms + proofs |
| Appendix | Full-text index | Searchable HTML |

**Acceptance Criteria:**
- [ ] Single PDF book (≤200 MB)
- [ ] Internal cross-references functional
- [ ] Search index built (ripgrep or similar)
- [ ] External links verified
- [ ] Published to Zenodo + IPFS

Once v1.0 ships, the system compounds:

1. **More validators** → More trustworthy ACRE claims
2. **More spoke nodes** → Greater mesh resilience
3. **More prototypes** → Climate-zone validation diversity
4. **More contributors** → Faster iteration cycles

**The infinite game:** Every new node makes the whole system stronger. No central authority required.
