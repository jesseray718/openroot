# Smart Contract Implementation Details — OpenRoot Token & Ledger System

**UNE:** DV.TECH.SOL01
**Date:** 2026-07-08
**License:** CC-BY-SA 4.0
**Target Chain:** Solana (Anchor framework)

This document outlines practical smart contract architecture for:
1. The existing ACRE token (PoPW with two-approval minting)
2. The expanded Contribution Ledger + Affiliate Coin system (lifetime affiliate rewards for anyone who builds)

## Current State: ACRE Token (acre_token.rs)

The current contract provides:
- Basic token minting with authority
- `mint_ppw_verified` instruction that accepts `work_units` and `proof_hash`
- Event emission for off-chain verification

**Limitations of current version:**
- Only one authority (needs expansion to two-approval / Kingdom Engine model)
- No project registry
- No automatic affiliate / royalty distribution
- No support for multiple coin types or lifetime affiliate tracking

## Recommended Architecture

We propose a modular but interconnected set of programs rather than one monolithic contract.

### Program 1: Core Contribution Ledger (Recommended as primary program)

**Responsibilities:**
- Register projects / workshops / infrastructure
- Track contributors and their ownership/affiliate percentages
- Mint Work Coins when verified contribution occurs
- Handle automatic affiliate distribution when value is generated from a registered project

**Key Accounts (PDAs):**
- `Project` account: Stores metadata, total affiliate percentage allocated, list of contributors + their % shares
- `Contributor` account (per project): Tracks individual affiliate entitlement
- `ContributionEvent` account: Records work done for minting

**Core Instructions:**
- `register_project` — Create a new project with initial contributors and affiliate splits
- `add_contributor` — Add someone to an existing project with their affiliate %
- `record_contribution` — Log verified work (can trigger coin minting)
- `distribute_affiliate` — Automatically send affiliate payments when revenue/value is recorded from the project

### Program 2: Multi-Token / Coin Factory

Instead of one token, we support multiple coin types that can be minted from the Contribution Ledger:

- Work Coin (general labor)
- Knowledge Coin (research, breeding, documentation)
- Health Coin (meals, detox protocols, herbal work)
- Infrastructure Coin (physical builds)
- Affiliate Coin (or integrated distribution logic)

This can be implemented as:
- One mint authority per coin type, controlled by the Contribution Ledger program, OR
- A single unified “Value Coin” with metadata tags for different contribution types

### Program 3: ACRE Token (Evolved)

Keep or refactor the existing ACRE contract to:
- Require two independent approvals (Kingdom Engine style) for PoPW minting
- Accept verified contribution events from the Contribution Ledger program
- Possibly become one of the coin types in the broader system

## Affiliate Tracking & Lifetime Rewards

**Design for “Anyone who builds gets paid for life”:**

When a project is registered:
- A percentage (e.g. 2–5%) of future value/revenue generated by that project is reserved for affiliate distribution.
- The remaining percentage goes to ongoing operators or the broader pool.
- Every contributor listed on the Project account receives their proportional share automatically when `distribute_affiliate` is called.

**On-chain vs Off-chain Tradeoffs:**
- Fully on-chain affiliate distribution is transparent but can be expensive if called too frequently.
- Recommended hybrid: Record value events on-chain, then use a crank/keeper or batch distributor (can be a small program or off-chain service with on-chain verification) to push affiliate payments periodically.

**Royalty / Affiliate Mechanism on Solana:**
Similar to Metaplex royalty enforcement but extended to ongoing affiliate rather than one-time secondary sales. Use a dedicated `AffiliateDistributor` account per project.

## Security & Upgradeability Considerations

- Use PDAs extensively for project and contributor accounts so only the program can modify them.
- Implement proper access control (only verified contributors or the Kingdom Engine can add contributors or record contributions).
- Consider program upgrade authority with a multisig or DAO-controlled upgrade path.
- Add timelocks or approval requirements for large affiliate distributions or project modifications.
- Include clear event emission so off-chain indexers and the transparent ledger can track everything in real time.

## Integration with Teams of 50 & Agape Principles

- A Team of 50 can register as a contributor entity on projects they build.
- Affiliate income can flow to the team wallet or be further distributed internally according to team agreements.
- The transparent ledger makes mutual aid visible — teams can see who is contributing and who needs support.
- Coins minted for scientific/knowledge work or health work directly support the agape health protocols and plant breeding program.

## Phased Implementation Roadmap

**Phase 1 (Current):**  
Refactor existing ACRE token to support two-approval minting and emit better events.

**Phase 2:**  
Build the Contribution Ledger program with project registration and basic contributor tracking.

**Phase 3:**  
Add automatic affiliate distribution logic (hybrid on-chain recording + periodic distribution).

**Phase 4:**  
Expand to multiple coin types and full integration with off-chain transparent ledger views.

**Phase 5:**  
Add governance / Kingdom Engine integration so major parameters (affiliate percentages, approval thresholds) can be adjusted through the DAO.

## Summary

The smart contract layer should move from a simple PoPW mint to a full Contribution Ledger that:
- Registers real-world projects
- Tracks everyone who builds them (regardless of when they joined)
- Automatically distributes lifetime affiliate rewards when value is generated
- Supports multiple contribution types through different coins or tagged value
- Remains transparent and auditable on-chain while staying practical on Solana

This architecture directly supports the shift from extraction-based government to a contribution-based, agape-oriented system where building creates ongoing value for the builder and the community.
